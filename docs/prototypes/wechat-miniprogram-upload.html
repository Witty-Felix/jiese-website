小程序打卡流程：骨架已落定为「A · 分步向导」

本页原本并列三个结构不同的流程骨架，回答「成员从打开小程序到『已记录』，中间应该被怎样分段」。2026-10-01 已选定 A。B / C 保留在底部切换条里作备查，不再作为候选。「结果未知」的新交互是待确认草案，供你直接点状态、评文案。

已落定的三项决策（2026-10-03 更新）
骨架定为 A · 分步向导——把「选材料 / 确认上传 / 看结果」拆成三个互斥步骤，推进前要求勾选确认。
导入链省去第 ③ 段「已选暂存页」，选完直接落子。原生选择器的「确定」即最终确认，不再多一层「已选文件 1/20 + 确认导入」。
导入链省去第 ① 段「空态引导页」，改为一点即弹选择器。点「从微信聊天选择」直接拉起原生选择器。两项合计 → 本项目没有任何自建的小程序页面，只调一次 chooseMessageFile。
结果未知主动作是「重交本次登记」：复用同一个 submission_id。若服务端返回 already，明确说「此前已登记，本次未新增」，不把它说成又成功一次。
辅助路径保留「去打卡榜核对」，但说明榜单最长约 60 秒才一致；它不能用「暂时没显示」证明「没有登记」。
