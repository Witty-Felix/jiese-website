# ADR 0006 — 删除权限收敛到管理员：独立管理密码 + KV 审计

日期：2026-09-25
状态：已接受

## 背景

用户明确要求：只有管理员能删除用户数据；**ima 知识库内容例外——不提供任何经本站的删除通道，只能在 ima 客户端自行删除**。

现状约束：

- 认证体系是昵称 + 共享邀请码（ADR-0002），全员同权，无法区分管理员。
- 站内持有的用户数据只有 KV 打卡统计记录 `checkin:<日期>:<昵称>`（ADR-0004）；打卡内容本体都在 ima KB「戒色」（ADR-0003），而 ima OpenAPI 只写不删。

## 决策

1. **数据边界（硬约束）**：站内删除功能只作用于 KV 打卡统计记录（`checkin:*` 前缀）。Functions 不持有、不调用任何 ima 删除接口；ima 内容一律引导用户去 ima 客户端自行删除。
2. **管理员认证**：新增 Pages Secret `ADMIN_PASSWORD`。删除请求须携带 `{ admin_password, operator, ... }`，服务端**常量时间比对**密码，通过才执行。不建管理员名单、无会话、无状态。解锁校验经 `POST /api/admin/verify`（同样常量时间比对），校验通过后前端把密码存 sessionStorage、随每次删除请求携带。
3. **删除粒度**：两种，同一个端点 `DELETE /api/admin/checkin`：
   - 单条：`{ nickname, date }` —— 删某用户某天的统计记录（该用户当天可重新打卡）。
   - 整户清空：`{ nickname, all: true }` —— 删该昵称全部 `checkin:*` 记录，从打卡榜消失。
4. **前端入口**：打卡榜角落放不起眼的「管理」入口 → 输入管理密码解锁为管理模式（密码存 sessionStorage，随每次删除请求发送，不落 localStorage）→ 榜单行内出现删除按钮。单条删需二次确认；整户清空需**手动输入该用户昵称**确认。
5. **审计**：每次删除成功后写一条 KV 审计记录，键 `audit:del:<ISO时间戳>:<operator>`，值含目标昵称、删除范围、删除条数。审计只写不读——需要追责时到 Cloudflare KV 控制台按前缀查看，不做界面。

## 理由

- **最小新增面**：一个 Secret、一个端点、一个前端开关，完全复用 ADR-0002 的无会话、无用户表风格，符合 Graph Engineering「最简单、可靠、经济」。
- 昵称即身份（ADR-0002），整户清空按昵称前缀删除与现有数据模型语义一致。
- ima 侧 OpenAPI 本就没有删除接口，且用户明确要求不碰；显式声明这条边界，避免未来有人「顺手」做出站内删 ima 的假象（站内删了、ima 还在，才是真事故）。
- 常量时间比对成本近零，消除时序侧信道；审计一条 KV 写入成本近零，换来可追溯。

## 后果

- **知道管理密码者即为管理员**：密码泄露 = 全部统计可删。密码仅存 Pages Secret，泄露后在 Cloudflare 后台更换即可，无需改代码。
- 无速率限制、无失败锁定：管理密码可被暴力尝试。熟人小圈子风险可接受；若风险上升，后续可加 KV 失败计数或改用长随机密码（升级路径，不阻塞本期）。
- 删除单条后，该用户当天可重新打卡（重新打卡会再次写入 KV）——预期行为。
- 整户清空后榜单不再显示该用户，但其 ima 文件夹与内容仍在——这是**预期行为**，站内不做任何 ima 侧联动。
- 审计记录只写不读，普通成员不可见（`/api/stats` 只扫 `checkin:` 前缀），也不占打卡榜。
- **KV list 最终一致（变更同步最长约 60s）**：删除后立即重拉 `/api/stats` 会短暂「复活」已删记录，刷新也无济于事。缓解：删除响应即时返回该用户重算后的榜单行 `row`（重算时显式排除刚删的键），前端据其本地乐观更新、不回源重拉；`/api/stats` 加 `Cache-Control: no-store` 防止再叠加浏览器/中间层缓存。
