# ADR 0004 — 打卡统计存 Cloudflare KV，全员可见

日期：2026-09-25
状态：已接受

## 背景

用户明确要求：每个用户能看到其他用户的打卡天数。ima OpenAPI 只写不读（无导出接口），统计数据无法从 ima 取回，必须有独立存储。

## 决策

引入 **Cloudflare KV**（唯一的新增存储依赖）：

- `POST /api/checkin` 成功落库 ima 后，同步写入一条打卡记录：键 `checkin:<yyyy-mm-dd>:<昵称>`，值含附件上传结果摘要。
- `GET /api/stats` 汇总全量记录，返回每个用户的：累计打卡天数（自然日去重）、当前连续天数、最近打卡日期，前端渲染成全员打卡榜。
- 同一用户同一天重复打卡：ima 侧正常再传（多次打卡留痕），统计侧按自然日去重，不重复计天。

## 理由

- KV 是 Cloudflare 生态内最轻的键值存储，无 schema、免运维，免费额度远超本站量级（几十人×每天一条）。
- 不引入 D1（关系库）：当前只有「按用户聚合打卡日期」一种查询模式，KV 足够。

## 后果

- 统计数据（昵称+日期）与 ima 内容是两套存储，二者可能短暂不一致（ima 落库成功但 KV 写失败）——Function 内 ima 成功后再写 KV，失败时仍返回打卡成功但在响应中标记统计未更新，可接受。
- 打卡内容本身不走 KV，防滥用仅靠邀请码与体积校验。
