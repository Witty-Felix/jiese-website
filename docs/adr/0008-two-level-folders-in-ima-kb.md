# ADR 0008 — ima 知识库内的两层目录：登录建用户文件夹、打卡建日期文件夹

日期：2026-09-25
状态：已接受（已在生产知识库端到端验证）
关联：**部分取代 ADR-0003**；ADR-0004（KV 统计口径不变）、ADR-0006（删除边界不变）

## 背景

v1.0 把一次打卡产生的三样内容（打卡笔记、运动截图、阅读录音）全部平铺在 ima KB「戒色」的根目录里，只能靠标题里的昵称与日期辨认。成员一多、日子一长，根目录变成一条长流水，检索成本随打卡总量线性上升；且内容归属只能从标题推断，缺少「目录」这一层结构性事实。

ADR-0003 曾计划按用户建文件夹，但其验证结论认定 **OpenAPI 无 `create_folder` 接口**，于是设计了一条从未启用的回退路径：管理员在 ima 客户端手工预建文件夹，再把「昵称 → folder_id」映射以 JSON 存进 Pages 环境变量 `IMA_USER_FOLDERS`。

本次实测**推翻了该结论**：接口存在。教训是官方 `api.md`（1.1.3 为最新）并未收录该类接口——**服务端跑在文档前面，能力必须以实测为准**。

## 决策

在 ima KB「戒色」内建立**两层**目录：

```
「戒色」
└── <昵称原文>          ← 用户文件夹
    └── YYYY-MM-DD      ← 日期文件夹
        ├── 打卡笔记
        ├── 运动截图
        └── 阅读录音
```

- 用户文件夹：在登录校验端点 `POST /api/verify` 执行「确保存在」。
- 日期文件夹：在打卡入库端点 `POST /api/finalize` 中，于任何 `add_knowledge` 之前创建。
- 上传凭证端点 `POST /api/prepare` **不改动**（`add_knowledge` 只发生在 finalize）。
- 三样内容的**标题一律不变**——标题在跨文件夹检索时仍是日期线索。
- 层级固定为两层，不引入月份层。
- 前端零改动：成员不感知目录结构。

### 已实测的接口契约（`POST /wiki/v1/create_folder`）

| 能力 | 实测结果 |
|---|---|
| 创建文件夹（支持嵌套） | ✅ 可用；请求 `{ knowledge_base_id, name, folder_id? }`；返回 `data.media_id` 即 folder_id |
| **父级字段名** | 就是 `folder_id`；写成 `parent_folder_id` 之类会被 **protojson 静默忽略**，文件夹落到根目录且**不报错** |
| 同父级重名 | 返回 `code 220001 已存在同名知识`；**非幂等**，因此必须「先查后建」 |
| 重名作用域 | **仅同一父级内冲突**，不同父级可同名 ⇒ 各成员的日期文件夹不会互撞 |
| 传入不存在的父级 ID | **不报错**，静默落根目录 ⇒ **写入后必须回读校验** |
| 移动已有条目 | ❌ `move_knowledge` 存在但**实测在任何配置下都是空操作** |
| 删除 | ❌ 不存在任何删除端点 |
| 浏览 | ✅ `get_knowledge_list` 按 `folder_id` 天然过滤；单页上限 50；文件夹条目为 `media_type: 99`，名称在 `title` |
| 分页终止 | 只认 `is_end`：**`next_cursor` 即使已到末尾仍返回非空串** |

### 「确保存在」原语：查 → 建 → 回读

`functions/api/_ima.js` 暴露两个接口，并**移除**既有的 `getUserFolder(env, nickname)`（`IMA_USER_FOLDERS` 回退路径随之退休，不再维护一条从未启用过的死分支）：

- `ensureUserFolder(env, nickname)` → `folder_id | undefined`
- `ensureDayFolder(env, userFolderId, date)` → `folder_id | undefined`

语义：

1. 枚举父级条目（根目录，或该成员的用户文件夹），命中同名文件夹则复用 `folder_id`。
2. 未命中才创建。
3. **创建后回读父级**：既确认文件夹确实落在预期的父级下（父级无效时会被静默落根），也顺带吸收并发的 `220001` 码（重新枚举即取回已存在的 `folder_id`）。
4. 任何失败都返回 `undefined` 并写告警日志，**绝不抛出**。

**大小写敏感（按昵称原文精确匹配）是刻意的**：必须与 `checkin:<日期>:<昵称>`、榜单行、删除审计完全同一口径。历史上确实同时出现过 `witty-felix` 与 `Witty-Felix`，它们在榜单上本来就是两个身份；文件夹若「聪明地合并」，会产生「一个人两个文件夹、榜单两行」的外溢矛盾。此处**一致性优先于便利性**。

**不做 `folder_id` 缓存**：根目录条目数 ≈ 成员数，一页即可枚举完，登录是低频动作。缓存的唯一收益是省一次列表调用，代价却是引入一条必须处理的失效路径——成员随时可能在 ima 客户端删掉或重命名文件夹，缓存值会变成悬空 id 导致入库失败。等成员数接近 50 再引入不迟。

### `ensureDayFolder` 的父级为何是显式参数

规格原写作 `ensureDayFolder(nickname, date)`。实现改为把**父级 folder_id 显式传入**，使这条硬约束成为**签名层面的保证**而非运行时判断：

> 日期文件夹**必须始终建在自己的用户文件夹内，否则就不建**。

若允许「用户文件夹不可用时刻在根目录建当天日期文件夹」，则两位成员的文件夹同时不可用、且同一天打卡时，第二个人会因「已存在同名知识」而复用第一个人的日期文件夹——**两人的内容会被静默混进同一个文件夹**。这是数据归属错误，比目录不整齐严重得多。父级显式化后，`ensureDayFolder(env, undefined, date)` 直接返回 `undefined`，错误不可能发生。

### 与规格的两处偏差（已评审接受，2026-09-26）

实现与 issue #1 的规格有两处**刻意**的差异，均经维护者评审后接受：

1. `ensureDayFolder` 的第二个参数由规格所写的 `nickname` 改为**显式父级 `userFolderId`**，理由见上一节。
2. `/api/finalize` 的成功响应**新增** `folder: "day" | "user" | "root"`——规格的「API 契约变更」一节只规定了 `/api/verify` 的 `folder` 字段。依据是降级表「任何降级发生 → 响应中如实暴露降级事实」，且 `root` 正是 User Story 17 所需的「有内容落在根目录」信号。

两处均为新增字段、向后兼容，前端不消费。

### 降级：打卡与登录永不因文件夹失败

| 情形 | 行为 |
|---|---|
| 登录时无法确保用户文件夹 | 登录**照常成功**；响应 `folder: "degraded"` |
| 提交打卡时用户文件夹不可用 | 三样内容落**知识库根目录**，且**不创建日期文件夹** |
| 用户文件夹可用、日期文件夹建不出 | 三样内容落**用户文件夹** |
| 任何降级发生 | 响应中的 `folder` 字段与 `console.warn` 如实暴露，不静默隐藏 |

`POST /api/verify` 成功响应新增 `folder: "ready" | "degraded"`；`POST /api/finalize` 成功响应新增 `folder: "day" | "user" | "root"`（**落库层级**，`root` 即「存在因降级落在根目录的内容」的信号，供管理员安排人工归位）。两处均为**新增字段，向后兼容**，前端不消费。

## 后果

- 知识库结构规整：按昵称浏览全部打卡、按日期核对当天三样内容都成立；榜单的一行可直接对应到一个文件夹。
- 目录结构与 KV 统计**互不牵连**：打卡天数与连续天数的口径一字未改。
- 站内**依旧不存在任何删除 ima 内容的通道**，原隐私承诺不变。
- 登录延迟增加 1 次列表读取（数百毫秒量级）；仅在**首次**建档时多一次创建 + 一次回读校验。均已评估接受。
- **空文件夹不可回收**：登录即建档意味着昵称打错或中途放弃会留下空文件夹，且 OpenAPI 无删除端点，只能到 ima 客户端人工删。已评估接受；若实践中变多，纠正成本极低（把建档时机从登录挪到入库即可）。
- **无自动归位能力**：`move_knowledge` 实测无效，现存根目录下的历史内容由维护者在 ima 客户端手工拖拽。
- 文件夹总量随「成员数 × 天数」增长，手工浏览历史日期时需要翻页（50 条/页）；日常打卡只按名字查当天的文件夹，不受影响。成员文件夹内超过一页时靠 `is_end` 翻页查找，已覆盖测试。
- 枚举设了 10 页（500 条）上限以防御游标异常导致的无界翻页。实测列表为**新→旧**排序，当天新建的日期文件夹必落在第一页，因此该上限只在极端规模下才起作用——届时需要按 `folder_id` 缓存（本期已明确不做）。

## 验证

- **桩化回归测试**（唯一接缝 = 端点处理函数边界，出站 HTTP 用可编程假实现替代）：40 项断言全绿。覆盖建档父级、三样内容同一个 `folder_id`、同日重复提交复用、大小写敏感、`220001` 吸收、分页命中、以及四级降级（含「静默落根」被回读校验识破）。
- **生产端端到端**（真实凭证 + 真实 COS 直传，KV 用内存桩以免污染线上榜单）：测试昵称 `zz_v11·test-a`（含 `·` 与 `-`）走完登录 → 直传 → 打卡，回读确认 `戒色 / zz_v11·test-a / 2026-09-25 / {笔记, 截图, 录音}` 两层结构落位正确，根目录无混入。
- **幂等复用**：对同一昵称与日期重跑两个原语，返回的 folder_id 与首轮完全一致，未重复创建。
