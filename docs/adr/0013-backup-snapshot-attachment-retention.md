# ADR 0013 — 备份、快照与附件 168 小时清理的一致性

日期：2026-10-03  
状态：已接受  
关联：[决定：备份、快照与附件 168 小时清理的一致性](https://github.com/Witty-Felix/jiese-website/issues/24)、[决定：附件 7 天到期的计时、清理与备份保留规则](https://github.com/Witty-Felix/jiese-website/issues/19)、[决定：自有服务器的数据模型与接口边界](https://github.com/Witty-Felix/jiese-website/issues/22)

## 背景

自有服务器迁移后，正式打卡记录需要长期保留，但截图和录音原文件必须从成功登记起连续保留 168 小时，之后不可访问、不可恢复。只删除生产目录并不足以满足这一目标：附件字节可能还存在于临时目录、缓存、数据库大对象、云盘快照、整机备份或远程灾备副本中。

本 ADR 定义记录备份、附件字节副本、云盘快照、恢复流程、容量保护和清理审计的边界。它不执行备份配置、生产清理、服务器迁移或数据恢复。

## 决策

### 1. 备份对象分为记录类与附件字节类

#### 记录类（长期可保留）

以下内容属于长期业务事实，可以进入长期备份并按记录策略保留：

- `member`、`submission`、`checkin_day` 的长期记录；
- 正式附件的元信息、`retained_until`、访问/留存/清理状态、错误和重试次数；
- `migration_record`、`audit_event` 及必要的迁移和生命周期对账信息；
- 数据库结构、应用配置和不含秘密的运维元数据。

记录备份不得包含管理密码、邀请码、私钥、访问令牌或完整附件字节。秘密使用独立的安全存储和轮换机制，不把备份当作秘密管理器。

#### 附件字节类（受 168 小时期限约束）

截图和录音的原始字节，无论位于生产附件目录、上传临时目录、缓存、数据库大对象、快照、备份还是复制副本，都属于附件字节副本。它们共享原始正式附件的到期边界：

- 正式附件的访问截止时间仍为 `retained_until = finalized_at + 168 小时`；
- 任何灾备或迁移副本都必须带有不晚于原附件 `retained_until` 的 `purge_at`；
- 到期前不得把备份恢复成新的留存期限；
- 到期后不得把附件字节留在可恢复副本中。无法证明已销毁的副本不能标记为“已清理”。

长期记录备份默认不复制附件字节。若为到期前的灾难恢复临时创建附件副本，该副本必须纳入附件清理清单、加密保存，并在 `purge_at` 到达时销毁和审计；不能借备份保留策略延长附件寿命。

### 2. 记录备份频率与保留

记录数据采用“增量/日志 + 完整备份”的组合：

- 增量变更或等价的恢复日志至少每小时形成一个可恢复点，目标 RPO 不超过 1 小时；
- 每天至少生成一次完整记录备份；
- 记录备份的远程副本默认保留 30 天；更长期的业务记录由生产数据库和经过核验的长期导出承担，不通过保留附件字节实现；
- 每次备份记录开始/结束时间、覆盖范围、校验结果、工具/规则版本和失败原因；失败不得被算作成功备份。

备份频率和保留周期是记录类策略，不改变任何 `submission` 或 `attachment` 的 `retained_until`。

### 3. 云盘快照不得成为附件字节的长期副本

云盘快照采用独立存储边界：

- 长期快照只覆盖系统、数据库、配置和其他不含附件字节的数据；
- 正式附件和上传临时对象必须位于不参与长期快照的附件存储边界；
- 如果底层云盘只能按整盘创建快照、无法排除附件路径，则该整盘快照不得作为长期快照保留；
- 生产目录删除、数据库状态更新或访问控制变化，均不能单独证明快照中的附件字节已经销毁。

短期故障恢复期间若不得不生成含附件的快照，必须像其他附件副本一样记录每个涉及附件的最晚 `purge_at`，并在期限到达前销毁整个含附件快照；无法做到逐对象核验时，按其中最晚到期对象的期限整体销毁。

### 4. 恢复必须先隔离，再按原期限校验

任何旧备份或快照恢复都必须进入隔离环境，恢复期间不接入公网、不签发附件访问授权。恢复流程为：

1. 恢复记录、附件元信息、清理状态和审计数据；
2. 校验记录与附件副本的时间、稳定 ID、大小、MIME、校验和及来源关系；
3. 对 `retained_until <= 当前服务端时间` 的附件立即强制不可访问并进入物理销毁队列，不得重新计算 168 小时；
4. 只有仍在留存期内、来源关系完整且校验通过的附件，才允许在切换后签发不超过原 `retained_until` 的短期访问授权；
5. 对象缺失、校验失败、时间矛盾或来源不明的附件标为 `unavailable`/待核验，不阻断长期记录恢复，也不得对外提供附件；
6. 完成到期扫描、补偿清理、容量检查和审计记录后，才允许切换流量。

恢复失败或清理失败时，记录仍可恢复并保持可查询，但对应附件继续不可访问；恢复不能把过期附件变成新的正式附件，也不能把清理失败伪报为已清理。

### 5. 加密、权限和恢复审计

- 记录备份和任何临时附件副本均须加密保存和传输；加密密钥与备份对象分离存放并独立轮换；
- 应用运行凭证、备份凭证和恢复凭证分离，默认禁止应用进程读取备份仓库；
- 恢复、下载、销毁和延长/变更备份保留策略属于 break-glass 操作，须最小权限、双人或等价审批、短时授权，并写入追加式 `audit_event`；
- 备份仓库不得公开访问，不能通过猜测对象路径、永久 URL 或快照挂载绕过附件期限；
- 审计内容不得包含管理密码、邀请码、访问令牌或完整附件字节。

### 6. 磁盘容量不足时的保护顺序

容量保护按以下顺序执行：

1. 优先保护长期记录、附件元信息和清理审计；
2. 保护仍在 168 小时留存期内的正式附件；
3. 立即清理已到期附件、孤儿附件和临时文件；
4. 可用空间低于阈值时告警；无法安全接收新文件时暂停/拒绝大文件上传，并返回明确、可重试的错误；
5. 分别记录“容量低于阈值”和“写入失败/服务受限”事件；
6. 不得为了腾出空间删除长期记录、清理审计或尚未到期的正式附件。

容量不足不能改变 168 小时规则，也不能让清理任务跳过访问禁用、审计或幂等状态更新。

### 7. 清理审计长期保留

附件清理和附件副本销毁的审计记录长期保留，至少包含：附件稳定 ID、提交 ID、来源/副本类别、原始 `retained_until`、实际执行时间、结果、错误类别、重试次数、任务版本和是否由恢复/人工操作触发。

“已到期”“已禁止访问”“删除请求已发出”和“实际删除成功”是不同事实；只有实际删除成功，才可把对应副本标为 `cleaned`。目标不存在按幂等成功处理，但仍记录该事实和来源。

审计只保存证明生命周期和清理结果所需的元数据，不保存被删除的附件字节或敏感认证材料。清理失败保持不可访问、可重试并可追溯，不影响 `submission`、`checkin_day` 或打卡天数。

## 验收门槛

备份和恢复方案在上线前必须能证明：

- 记录备份与附件字节备份明确分离；长期备份中没有可恢复的过期附件字节；
- 任意含附件的临时副本、快照和备份都能追溯到附件 ID、`purge_at` 和销毁证据；
- 恢复到隔离环境不会重置 `retained_until`，过期附件在开放流量前不可访问并进入清理；
- 缺失或校验失败的附件不阻断记录恢复，也不会被伪报为可用或已清理；
- 记录备份达到每小时 RPO 目标，完整备份和远程副本可校验；
- 低容量时优先清理临时/到期对象并暂停危险上传，不牺牲长期记录或未到期附件；
- 清理成功、失败、重试、恢复和人工 break-glass 操作均能在长期审计中重建。

## 后果

- 长期备份恢复可以保住打卡历史，而不会借恢复过程复活过期截图或录音。
- 附件存储必须与数据库/系统快照形成明确边界；在只有单块云盘且无法排除路径时，不能把整盘快照当作长期灾备方案。
- 实现需要副本清单、`purge_at`、清理租约、恢复前扫描和容量告警；这比“定时删生产目录”复杂，但能满足不可恢复目标。
- 记录备份默认只保留 30 天的远程副本，若业务需要更长的记录恢复窗口，应单独设计不携带附件字节的归档，不得延长附件寿命。

## 不在本 ADR 范围

- 具体数据库、对象存储、备份供应商和部署编排；
- 实际备份凭证、密钥、服务器配置和容量阈值数值；
- 生产数据迁移、历史导入、DNS 切换和真实附件删除执行。
