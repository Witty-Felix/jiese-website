# ADR 0012 — 旧 KV/ima 历史迁移批次、所有权切换与回滚边界

日期：2026-10-03  
状态：已接受  
关联：[决定：已有 ima 内容和 KV 打卡记录如何过渡到新系统](https://github.com/Witty-Felix/jiese-website/issues/20)、[决定：自有服务器的数据模型与接口边界](https://github.com/Witty-Felix/jiese-website/issues/22)

## 背景

自有服务器上线前，旧系统同时拥有两类不能互相替代的来源：KV 中可枚举的 `checkin:<日期>:<昵称>` 统计键，以及 ima 中可能仍存在的笔记、截图和录音。KV 只能证明有限的打卡统计；ima 的可读、可导出、可删除能力还必须逐项核验，不能把标题、猜测时间或“迁移程序跑过”当成完整历史和清理事实。

本 ADR 定下历史迁移、旧附件关联、写入所有权切换和回滚的边界；不执行生产导入、复制、DNS 切换或删除。

## 决策

### 1. 以迁移批次和不可变清单为审计边界

每次迁移使用唯一 `migration_batch_id`，先做只读预检，再在旧系统写入已排空后生成最终清单。清单至少包含：

- `source_type`、稳定 `source_record_id`、昵称原文、`local_date`、来源状态和错误原因；
- KV 原始值的 SHA-256、ima 对象的稳定标识及可取得时的字节 SHA-256、大小和 MIME；
- `ownership_cutover_at`（新提交所有权切换时刻）、`legacy_drain_deadline`（旧提交排空截止时刻）、观测时间、迁移工具/规则版本；
- 每条记录的目标实体、迁移状态、核验时间、`retained_until`、旧来源清理状态，以及整份规范化清单的 SHA-256。

最终清单在旧写入闸门关闭后执行“list 后逐键 get”的双重读取；若来源列表最终一致，重复扫描直到清单稳定，或由管理员将批次标为 `blocked`。清单稳定后才允许进入导入校验。清单和报告是可重跑的输入，不用工作目录中的临时文件代表事实。

### 2. KV 只导入可核验的打卡日，不伪造完整提交

- 严格按键名解析 `checkin:<YYYY-MM-DD>:<昵称>`；昵称保持大小写敏感，不归一化、不合并近似写法。每个有效键最多产生一个 `(member, checkin_day)`，同一天多次旧提交无法由 KV 统计键重建。
- 导入的是 `checkin_day` 的 `source=kv_import` 事实，并保存原键作为 `source_record_id`。若 KV 值中的 `ts` 经过旧版本规则、范围和时区校验，才把它记录为 `legacy_success_at`/可用于留存计算的时间；缺失、损坏、未来时间或无法证明是成功登记后的时间一律保持 `null`。
- 不为 KV 记录编造 `submission_id`、感悟、截图、录音、附件哈希或 ima 对象关系。没有对应证据的字段显示为未知，而不是空内容或“已迁移完整历史”。
- 最终快照中被 `deleted:<昵称>` 标记的日期不恢复为有效 `checkin_day`；该来源键仍在迁移报告中记为 `excluded_deleted`，以便证明没有把管理员删除的统计复活。旧来源中没有实际键的孤立删除标记不产生新记录。
- 若新系统在导入前已经为同一成员和日期产生了 native `checkin_day`，导入只补来源链接并把来源归为 `mixed`，不覆盖 native 的提交时间、感悟、附件或可见性，也不创建第二个打卡日。

### 3. 旧 ima 附件只有在四项证据齐全时才迁入

一个旧截图或录音只有同时满足以下条件，才可成为新系统的正式附件候选：

1. 能以昵称原文和 `YYYY-MM-DD` 唯一关联到一个已核验的旧打卡日；同日多个候选、只有标题相似、或无法区分截图/录音的，记为 `unmatched`；
2. ima 能提供稳定对象标识，并且迁移工具能够读取/复制字节，取得并记录大小、MIME 和 SHA-256；没有读取能力就不能声称已迁入；
3. 有可验证的成功登记时间。优先使用经过规则验证的旧 KV `ts`；没有时间或时间含义不确定时，记录为 `pending_verification`/`blocked`，不猜导入时间、文件创建时间或当前时间；
4. 已登记旧来源清理路径：可用的删除接口，或由管理员明确授权、指定执行人、验收证据和手工步骤的人工清理流程。没有清理路径的候选不得进入“已迁入且可回看”的状态。

旧 ima 笔记、无法唯一配对的多次同日提交和无法取得的正文只保留 `legacy_ref`/未匹配状态；不把它们包装成新的 native `submission`，也不凭标题生成感悟。旧内容是否另行导出属于后续范围，不影响 KV 打卡日迁移。

### 4. 两套附件清理状态完全分开，168 小时不允许猜算

对已核验的旧成功登记时间 `legacy_success_at`，新副本的 `retained_until` 固定为 `legacy_success_at + 168 小时`，使用服务端 UTC 计算；不以迁移时间重置计时。导入时已经到期的副本立即标为不可访问并进入清理队列，不因复制成功而重新开放 168 小时；不需要为了“看起来已迁入”而复制已过期字节。

新对象的 `cleanup_status=succeeded/cleaned` 只能表示新对象实际删除成功。旧 ima 对象另有 `legacy_cleanup_status`：只有删除动作实际执行并有可核验回执或人工验收证据，才能标为 `succeeded`。两者任何一个失败、无接口或无证据，都保持 `failed`、`blocked` 或 `manual_required`，绝不因为数据库状态改变、批次完成或新对象已删除而标记旧对象 `cleaned`。

缺失成功登记时间的旧附件不会得到临时的 168 小时窗口，也不会自动按“现在已过期”删除；它停在 `pending_verification`/`manual_required`，由管理员核验来源时间，或在旧 ima 客户端按人工清理授权处理。这样既不把未知事实伪造成已清理，也不把无法访问旧 ima 当成删除成功。

### 5. 导入先暂存，按来源键幂等，可从失败点继续

批次状态为 `planned → snapshotted → importing → verified → activated`，失败时进入 `blocked`，不删除已经写入的目标数据。导入记录使用 `(source_type, source_record_id)` 唯一键；旧 ima 附件还要以稳定对象标识、附件类型和来源哈希防止同一字节重复复制。

- 同一来源键再次执行时，若目标和校验和一致，视为幂等成功；若目标存在但校验和不一致，停止该记录并报告冲突，不覆盖目标。
- 每条记录单独保存状态和错误，失败重跑只处理失败/待核验项；已核验、已导入或已人工排除项不重复创建 `member`、`checkin_day` 或附件。
- `importing` 的历史记录处于批次暂存态，公开榜单和历史查询不读入未激活批次；只有对账通过后一次性激活。native 新提交不依赖批次激活，也不被回滚覆盖。

### 6. 采用“新提交立即切新、旧提交排空”的所有权切换

切换窗口不做双写，也不根据故障自动回退到旧系统：

1. 在 `ownership_cutover_at` 之前完成预检和演练。到达该时刻后，旧系统停止签发新的提交/上传会话；只有在切换前签发的旧 `submission_id` 允许继续由旧系统登记。
2. `ownership_cutover_at` 之后，所有新 `prepare` 只由自有服务器签发，后续上传和 `finalize` 只归自有服务器；即使旧系统不可用，也不把同一次未知结果自动改投新系统。
3. 旧系统保留到 `legacy_drain_deadline`，至少覆盖其现有提交/上传会话的最长期限。截止后关闭旧 `finalize` 写入，读取最终 KV 与删除标记快照，完成最终批次导入。仍处于未知结果的旧提交进入 `pending_verification`，不自动重新登记。
4. 新系统从切换时刻起就是新提交的唯一写入权威；旧 KV 和 ima 在批次完成后仅作为只读迁移来源。历史导入不得覆盖切换期间已经产生的 native 数据。

因此每次新提交都有唯一归属：切换前签发的 `submission_id` 属于旧系统，切换后签发的 `submission_id` 属于新系统，不能因为请求重试、回滚或临时故障跨边界重放。

### 7. 回滚只回退流量/版本，不回滚事实或把写入权交回旧系统

在切换闸门真正打开前，预检失败可以取消批次并继续使用旧系统。切换后若新服务故障：

- 若尚未有新系统成功登记，可把流量切到已验证的新系统旧版本，或进入维护态；
- 一旦有任何 native 新提交成功，不能再把新提交路由回旧 KV/ima，也不能删除新系统数据来制造“回滚”；只能回退到兼容的新版本、修复后重试，或暂停提交；
- 未激活的迁移批次可暂停/作废并从清单断点继续，已导入的目标记录保留作审计，不作为删除对象；需要纠正时以来源键和条件更新修正；
- 旧 ima 内容在本 ADR 下不自动删除。旧附件清理必须在迁移报告通过、清理授权存在且每个对象有实际删除证据后单独执行。

### 8. 验收门槛

迁移批次只有在以下材料齐全后才能标为 `verified`/`activated`：

- 批次清单、规则版本、各级 SHA-256、切换时刻、旧排空截止时刻和完整失败/重试记录；
- 按昵称、自然日的 KV 对账：所有未被删除标记排除的源键在新系统恰好有一个有效 `checkin_day`，总数和日期集合一致；被删除日期没有被复活；native 记录未被覆盖；
- 每个 ima 候选都有 `migrated`、`excluded_deleted`、`unmatched`、`blocked`、`pending_verification` 或 `manual_required` 等明确状态，没有静默丢失；仍待核验/人工处理的候选不得在公开历史中表现为可用附件；每个已迁入附件的来源/目标大小、MIME、哈希和对象关联一致；
- `retained_until` 能由已核验的成功登记时间重算，已到期附件不可访问；新对象和旧 ima 对象的清理状态分别对账，任何一方没有实际删除证据都不能写成 `cleaned`；
- 回滚演练证明新旧写入没有交叉归属，重试不产生重复打卡日或附件，批次可从任一失败点恢复。

本 ADR 不把“无法访问 ima 的删除接口”解释成清理完成；这种记录必须在报告中明确停在待核验/人工处理。

## 后果

- 历史榜单和统计可以可靠迁移，但不会伪造 KV 从未保存的感悟、附件或多次同日提交。
- 切换后新写入链路简单明确；代价是旧系统需要一个排空窗口，且未知结果不能靠跨系统自动重试解决。
- 导入可重跑、可对账、可暂停，但需要保存批次清单、校验和、暂存/激活状态和人工清理证据。
- 旧 ima 没有批量导出或删除能力时，附件会明确停在 `blocked`/`manual_required`，而不是以成功状态掩盖能力缺口。
